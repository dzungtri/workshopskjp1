AIを組み込んだシステム: どれを選ぶ？

RAG か Fine-tuning か

  • まず Prompt + RAG — 情報がよく変わる · 情報の元を見せたい
  • Fine-tuning — 形式 · 話し方 · 分類を大量に安定させたい時だけ
  • 多くの場合: RAG で知識、Prompt で動き方

どちらでも必須: Eval

「正解の例」を50〜100件 → 変更のたびに自動評価
= AI機能のテスト

工数 · コストの見積もり: PoC で 1件あたりのトークン × 件数 を実際に測ってから
⏱ 112:20–113:50 (1.5分)
AIを組み込んだシステムについてです。 RAG とファインチューニング、どちらを使うか。まずは Prompt と RAG から始めてください。 情報がよく変わる時や、情報の元を見せたい時は RAG です。 ファインチューニングは、形式や話し方、分類を、大量に安定させたい時だけです。 多くの場合、知識は RAG、動き方は Prompt、という組み合わせで十分です。 どちらでも必須なのは Eval です。正解の例を50件から100件作って、変更のたびに自動で評価します。AI機能にとっての「テスト」です。 外部APIか、自社運用か。外部APIは速く始められて、性能も最新です。データの扱いは、契約と地域を確認してください。 自社運用はデータを社内に閉じられますが、GPU、モニタリング、更新と、運用の負担が大きいです。 コストは、PoC で「1件あたりのトークン × 件数」を実際に測ってから見積もるのがおすすめです。
VN: RAG vs fine-tune: bắt đầu Prompt + RAG (dữ liệu hay đổi, cần nguồn); fine-tune chỉ khi cần ổn định format/giọng/phân loại số lượng lớn. Bắt buộc Eval (50–100 ví dụ chuẩn, tự đánh giá mỗi lần đổi). API ngoài vs tự vận hành: nhanh/mới nhất vs dữ liệu nội bộ nhưng nặng vận hành; kiểm tra hợp đồng/vùng dữ liệu. Ước tính chi phí = token/lần × số lần đo thật ở PoC.
