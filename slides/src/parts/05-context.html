コンテキストが埋まっていく様子を見てみます。左の箱がコンテキストウィンドウです。 【→】作業を始めると、ユーザー、アシスタント、ツールの結果が積み上がります。緑がツールの結果です。 【→】ファイルを読んで、テストを回して……どんどん増えます。 【→】8割を超えました。ここで精度が落ち始めます。 【→】1つ目の手、micro-compact。古いツールの結果を消します。 ファイルの中身は、必要ならもう一度読めばいいので、消しても安全です。 【→】でも、また埋まってきます。 【→】2つ目の手、auto-compact。会話全体を要約して、要約だけを残します。 注意点があります。要約すると、細かい数字や決定が消えることがあります。 だから「この決定と、失敗したテスト名は必ず残して」と、何を残すかを指示するのがコツです。 もっと良いのは、大事なことは最初からファイルに書いておくことです。

コンテキスト管理には、4つの戦略があります。 【→】Write、外に書く。計画、進捗、決定をファイルに書きます。さっきの Ralph Loop や feature list もこれです。 【→】Select、必要な時に選ぶ。リポジトリ全部を読ませません。grep や LSP で、必要な所だけ読みます。Skills も、必要になった時だけ読み込みます。 【→】Compress、圧縮する。古いツールの結果を消す。要約する。何を残すか指示する。 【→】Isolate、分ける。調査は subagent に任せて、要約だけ受け取る。タスクが変わったら /clear。 【→】うまくいっているエージェントは、この4つを全部組み合わせています。
VN: 4 chiến lược: Write (ghi ra file: plan/progress/quyết định), Select (chỉ đọc phần cần: grep/glob/LSP, skills nạp khi cần), Compress (xoá tool result cũ, tóm tắt có chỉ định giữ gì), Isolate (subagent điều tra trả tóm tắt, /clear giữa các task). Agent tốt kết hợp cả 4.

最後に、トークンを抑える工夫です。 【→】/clear。タスクが変わったら、机を片付けます。/compact は、何を残すか指示して使います。 【→】キャッシュ。プロンプトの先頭、system や CLAUDE.md をあまり変えないと、キャッシュが効いて安くなります。 【→】モデルの使い分け。簡単な作業は小さいモデル、難しい設計は大きいモデル。 【→】ツールの出力を短くする。テストの出力は、失敗だけ表示する、など。 【→】MCP は、使うものだけ有効にします。ツールの定義だけで、コンテキストを使うからです。 【→】そして、まず見ること。どこでトークンを使っているか。 【→】考え方です。安いモデルで3回やり直すのと、高いモデルで1回。どちらが安いでしょうか。 答えは「マージされたPR 1本あたり」のコストで比べないと分かりません。 【→】トークンを減らして、失敗が増えたら、逆に高くなります。精度とコストは、セットで測ります。 ここまでで質問はありますか？
