実際に動かしてみましょう。 タスクは「返品期限を過ぎても、返金されてしまう。直して」です。 【→ 1】ユーザーがタスクを渡します。これが最初のメッセージです。 【→ 2】モデルは考えます。でも、モデルは考えるだけです。自分でファイルは読めません。 だから「このファイルを読みたい」という tool_use を返します。 【→ 3】実際にファイルを読むのは、Tools、つまりハーネス側です。 結果がメッセージに追加されます。ここに「+1日」というバグがありますね。 【→ 4】モデルは Edit を頼みます。「+1」を消しました。 ……でも、実はここで、境界を間違えています。 【→ 5】次にテストを実行。1件失敗しました。「ちょうど8日後は返品できる」というテストです。 【→ 6】モデルは失敗の結果を見て、もう一度直します。テストは全部通りました。 ここが大事です。テストという「フィードバック」があったから、AIは自分の間違いに気づけました。 【→ 7】最後に、tool_use がなくなったら、ループ終了。報告して終わりです。 左の数字を見てください。ループは5回、コンテキストはどんどん増えています。 この「増えていく」が、パートEの話につながります。

中身は、たった 10行

messages = [{"role": "user", "content": task}]

while True:
    resp = model(system=SYSTEM,       # ① 指示
                 messages=messages,   # ② 記憶
                 tools=TOOLS)         # ③ できること
    messages.append(resp)
    if resp.stop_reason != "tool_use":
        break                         # ④ 終了条件
    results = [run(call) for call in resp.tool_calls]
    messages.append({"role": "user", "content": results})

⏱ 14:00–16:00 (2分) · → 4回
コードにすると、本当にこれだけです。約10行。 メッセージのリストを作って、while ループ。 モデルを呼んで、tool_use がなければ終わり。あれば、ツールを実行して、結果を戻す。 【→】考えるのは、モデルの仕事です。私たちは選ぶだけです。 【→】行動は、この run の部分。ここは私たちのコードです。 だから、ここで止めることも、記録することもできます。これがガードレールです。 【→】記憶は messages。ループのたびに増え続けて、いつか、いっぱいになります。これがコンテキスト管理の問題です。 【→】つまり、ガードレールもコンテキスト管理も、魔法ではありません。 このループのどこかに、入れるだけです。
VN: Code agent loop ~10 dòng. Trí thông minh = model; hành động = run() (code của mình → chặn/ghi log được = guardrail); bộ nhớ = messages (tăng mãi → tràn = context). Mọi kỹ thuật chỉ là "chèn vào đâu đó trong vòng lặp".

⏱ 16:00–18:30 (2.5分) · → 5回
ループを作る部品は、4つです。 【→】一つ目、System prompt。ルールや役割です。CLAUDE.md や AGENTS.md がここに入ります。 これが悪いと、ルールを無視したり、毎回違う動きをしたりします。 【→】二つ目、Messages。会話とツールの結果。つまりコンテキストウィンドウです。 これが悪いと、前のことを忘れたり、精度が落ちたり、コストが増えたりします。 【→】三つ目、Tools。何ができるか。ファイルを読む、書く、コマンドを実行する。 ここが一番危ないです。本番DBに触れる、なども起こります。パートBで話します。 【→】四つ目、Stop condition。いつ終わるか。 ここが弱いと、「終わりました」とウソの完了をしたり、無限ループになったりします。 【→】私の経験では、失敗の多くは「モデルが悪い」のではありません。 この4つの部品の、どれかの設計ミスです。
VN: 4 bộ phận: system prompt (CLAUDE.md), messages (context), tools (nguy hiểm nhất → B), stop condition (báo xong giả, vòng vô hạn → C/D). Lỗi thường không do model mà do thiết kế 4 phần này.
