# Feature Specification: 返品理由 (Return Reason) の追加

**Feature Branch**: `001-return-reason`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "返品申請に「返品理由」を追加したい。理由は 不良品・サイズ違い・イメージ違い・その他。理由によって返金のルールが変わる可能性がある。"

**関連業務ルール**: BR-09 (返品期限), BR-10 (開封・使用済は返金不可 / 不良品は可), BR-11 (部分返品), BR-12 (按分返金), BR-13 (冪等), BR-14 (返金上限)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 返品申請時に返品理由を選ぶ (Priority: P1)

購入者は返品を申請するとき、4つの返品理由 (不良品・サイズ違い・イメージ違い・その他) から1つを選ぶ。選んだ理由は返品申請に記録され、後から確認できる。

**Why this priority**: 理由が記録されないと、理由別の返金ルールも分析もできない。本機能の土台であり、これ単体でも「なぜ返品されたか」が分かるという価値がある。

**Independent Test**: 理由を指定して返品申請し、申請内容に理由が記録されていること、理由なし・定義外の理由は拒否されることを確認すれば単独でテストできる。返金額は既存ルール (BR-12) どおりで変わらない。

**Acceptance Scenarios**:

1. **Given** 受取済で返品期限内の注文, **When** 購入者が理由「サイズ違い」・未開封で1商品を返品申請する, **Then** 申請が受け付けられ、申請に理由「サイズ違い」が記録される
2. **Given** 受取済で返品期限内の注文, **When** 購入者が理由を指定せずに返品申請する, **Then** 申請は「返品理由が必要」というエラーで拒否され、注文の状態は変わらない
3. **Given** 受取済で返品期限内の注文, **When** 4つの選択肢以外の理由で返品申請する, **Then** 申請は「不正な返品理由」というエラーで拒否され、注文の状態は変わらない
4. **Given** 受取済で返品期限内の注文, **When** 理由「その他」と補足コメントを付けて返品申請する, **Then** 理由「その他」と補足コメントの両方が申請に記録される
5. **Given** 理由付きで返品申請された注文, **When** 返金を実行する, **Then** 返金額は返品理由に関係なく既存の按分返金ルール (BR-12) どおりに計算される (理由別ルールが決定されるまで)

---

### User Story 2 - 返品理由と商品状態の整合性チェック (Priority: P2)

既存ルール BR-10 では、商品状態が「不良品 (defective)」なら開封済でも返金可能になっている。新しく追加する返品理由「不良品」と、既存の商品状態「不良品」の関係を明確にし、矛盾した申請 (例: 理由は「サイズ違い」なのに状態は「不良品」) を扱えるようにする。

**Why this priority**: 「不良品」は返金可否に直接関わる (BR-10)。理由と状態の関係が曖昧なままだと、返金不可の商品が返金されたり、その逆が起きたりする。ただし P1 の記録だけでも価値があるため P2 とする。

**Independent Test**: 理由と商品状態の組み合わせを変えて返品申請し、決定されたルールどおりに受付・拒否されるかを確認する。

**Acceptance Scenarios**:

1. **Given** 受取済で返品期限内の注文, **When** 理由「不良品」・状態「不良品」で返品申請する, **Then** 申請は受け付けられ、BR-10 どおり返金対象になる
2. **Given** 受取済で返品期限内の注文, **When** 理由「イメージ違い」・状態「開封済」で返品申請する, **Then** BR-10 どおり返金不可として拒否される
3. **Given** 受取済で返品期限内の注文, **When** 理由と状態が食い違う申請 (例: 理由「不良品」・状態「開封済」、または理由「サイズ違い」・状態「不良品」) をする, **Then** [NEEDS CLARIFICATION: 返品理由「不良品」と商品状態「不良品 (defective)」の関係は? A) 同じものとして扱い、理由「不良品」なら状態も不良品とみなす / B) 独立した項目とし、返金可否は従来どおり状態のみで判定 (食い違いも許容) / C) 食い違う組み合わせはエラーで拒否する]

### User Story 3 - 返品理由によって返金ルールを変える (Priority: P3)

運営者 (PO) が決めた理由別の返金ルール (例: 不良品は全額返金、イメージ違いは返送料を差し引く 等) に従って返金額や返金可否が変わる。

**Why this priority**: 依頼文では「変わる**可能性がある**」とされており、具体的なルールはまだ決まっていない。業務ルール未決定のため、P1・P2 の後に PO 決定を待って着手する。

**Independent Test**: 同じ商品・同じ数量を異なる理由で返品し、理由ごとに決められた返金額になることを確認する (期待値は人間承認済みのゴールデンデータで定義する)。

**Acceptance Scenarios**:

1. **Given** 理由別返金ルールが業務ルールとして決定・承認済み, **When** 各理由で返品・返金する, **Then** 返金額は決定されたルールどおりになり、整数の円で、累計返金額は支払額を超えない (BR-14)
2. **Given** 理由別返金ルール, **When** [NEEDS CLARIFICATION: 理由によって返金ルールをどう変えるか? 本機能の範囲に含めるか? A) 今回は理由の記録のみ。返金ルールは変えず、別機能で PO 決定後に対応 / B) 今回の範囲に含める (その場合、理由ごとの返金額・返金可否・返送料負担・返品期限の違いを PO が業務ルールとして決定する必要あり) / C) 不良品のみ例外を設ける等、限定的なルールを今回決める]

---

### Edge Cases

- **1回の返品申請に複数商品が含まれ、商品ごとに理由が異なる場合**: 理由は「申請単位で1つ」か「商品ごとに1つ」か → [NEEDS CLARIFICATION: 返品理由は返品申請ごとに1つか、返品する商品 (明細) ごとに1つか? A) 申請ごとに1つ (理由が違う商品は別申請にする) / B) 商品ごとに1つ / C) 申請ごとに1つだが商品ごとの上書きも可]
- **本機能リリース前に作成された返品申請 (理由なし)**: 理由「未設定」として扱い、既存の返金処理 (BR-12〜14) はそのまま実行できる。新規申請でのみ理由を必須とする
- **「その他」で補足コメントが空**: 補足コメントは任意。空でも受け付ける
- **補足コメントが極端に長い**: 上限 (500文字) を超える場合は拒否する
- **同じ返品への二重返金**: 理由の追加後も BR-13 (冪等) を維持する。理由が違っても同じ返品IDなら二重返金しない
- **返品期限切れ**: 理由が「不良品」でも、BR-09 の期限 (受取から8日) は変わらない (期限の理由別例外は本機能の範囲外。TBD-01 にも影響しない)
- **部分返品を複数回**: 回ごとに異なる理由で申請できる。数量上限 (BR-11) は理由に関係なく合算で判定する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 返品申請には返品理由を必ず1つ指定しなければならない。理由がない新規申請は拒否する
- **FR-002**: 返品理由は「不良品」「サイズ違い」「イメージ違い」「その他」の4種類のみとし、それ以外の値は拒否する
- **FR-003**: 理由「その他」のときは、購入者が任意の補足コメント (最大500文字) を付けられる。他の理由でも補足コメントは任意で付けられる
- **FR-004**: 受け付けた返品申請には、指定された返品理由 (と補足コメント) が記録され、後から参照できなければならない
- **FR-005**: 理由の不足・不正による拒否の場合、注文の状態・返品履歴・在庫・返金は一切変化してはならない
- **FR-006**: 返品理由の追加によって、既存の返品・返金ルール (BR-09〜BR-14) の判定結果は変わってはならない (理由別ルールが業務ルールとして決定されるまで)。既存のゴールデンテストの期待値はすべてそのまま満たすこと
- **FR-007**: 返品理由「不良品」と商品状態「不良品 (defective)」の関係は User Story 2 の決定に従って扱わなければならない
- **FR-008**: 返品理由の単位 (申請ごと / 商品ごと) は Edge Cases の決定に従う
- **FR-009**: 本機能リリース前に作成された理由なしの返品申請も、従来どおり返金処理できなければならない
- **FR-010**: 理由別の返金ルールを導入する場合、そのルールは事前に業務ルール (business-rules) として PO が決定・承認し、ID を付与したものに限る。実装者が推測でルールを作ってはならない

### Key Entities

- **返品申請 (Return)**: 注文に対する返品の申請。返品する商品・数量・商品状態、申請日時、状態 (申請中 / 返金済) に加え、**返品理由** と **補足コメント** を持つ
- **返品理由 (Return Reason)**: 不良品 / サイズ違い / イメージ違い / その他 の4値。返品申請 (または返品明細) に紐づく
- **商品状態 (Condition)**: 既存の 未開封 / 開封済 / 使用済 / 不良品。返金可否 (BR-10) の判定に使われる。返品理由とは別の概念として既に存在する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 本機能リリース後の新規返品申請の 100% に、4種類のいずれかの返品理由が記録されている
- **SC-002**: 理由の不足・不正な申請は 100% 拒否され、拒否された申請によって注文・在庫・返金が変化したケースが 0 件である
- **SC-003**: 既存の返金計算 (按分返金・冪等・上限) の人間承認済み期待値と、本機能導入後の返金額の差異が 0 件 (0円) である
- **SC-004**: 購入者は返品申請の際、追加の操作1回 (理由の選択) だけで理由を指定でき、申請完了までの時間が従来比で大きく増えない (目安: 増加 30秒以内)
- **SC-005**: 記録された返品申請データだけを使って、返品理由ごとの件数を漏れなく (理由不明 0 件、「未設定」の旧データを除く) 数えられる

## Assumptions

- 返品理由を選ぶのは購入者本人。運営者による理由の後からの変更は本機能の範囲外
- 理由の表示名は日本語の4種類で固定。選択肢の追加・変更は業務ルールの変更として PO 承認を要する
- 補足コメントの上限は 500 文字 (一般的な問い合わせフォームの水準)
- 既存の返品申請データには理由がないため「未設定」として扱い、遡って理由を必須にはしない
- 理由別の返金ルールは現時点で `docs/business-rules.md` に存在しない。決定されるまでは理由は「記録のみ」で返金額に影響しない
- 返品期限 (BR-09)・部分返品 (BR-11)・按分計算 (BR-12)・冪等 (BR-13)・上限 (BR-14) は変更しない。TBD-01・TBD-02 にも本機能では触れない
- 決済 (payment) 側の仕組みは変更しない
- 理由別の集計画面・レポート機能は範囲外 (集計できるデータを残すところまでが範囲)
